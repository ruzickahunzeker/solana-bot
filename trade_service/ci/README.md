# CI-only locked Git sources

The first isolated CI run, `43666176316` at commit `ffc506e`, failed before
compilation: `MeteoraAg/zap-program` returned 404/authentication failure for the
revision already in `Cargo.lock`. No Rust tests ran in that attempt.

`locked-git-sources.toml` replaces only that exact Git source for CI commands.
It is not a project `.cargo/config.toml`, dependency patch, SDK upgrade, new
resolver baseline, or production build configuration. Cargo.lock and the SDK
vendor are unchanged. Registry dependencies and the other Git source still use
their existing locked identities.

The three package directories were generated by `cargo vendor --locked
--versioned-dirs` from the existing clean Cargo Git checkout:

- Repository: `https://github.com/MeteoraAg/zap-program`
- Commit: `064c58b317b9a85f212c0de72caea286fc72fdb4`
- `libs/jupiter` tree: `e1e8d0198895abb85921e8be756ce2c89fd0f4ac`
- `protocol-zap` tree: `6a63acadd65551d64bac68bb86b8b842412b21fc`
- `zap-sdk` tree: `f56cd6f79a73d7fd01eeed33fee940cca70c8c32`

All exported Rust/source files were compared byte-for-byte with that checkout.
Cargo normalizes the package manifests when vendoring. Its per-file inventories
are retained and independently checked by `scripts/test_ci_git_sources.py`.
Anchor's `declare_program!(jupiter)` also searches manifest ancestors for the
original workspace-level `idls/jupiter.json`, which Cargo vendor omits. The
unchanged IDL is retained in `ci/idls/jupiter.json`, separately hash-checked:
Git blob `891d8a2c7588deb39231f671b6cead25dbad78a0`, SHA-256
`d1dc2e8726886dbdcde16b52bc5dd239779ec4a56f164b9444ac347677267a3e`.
This is reproducibility evidence, not new upstream authenticity or licensing
assurance. The checkout has no license file; retain this snapshot only in the
existing private validation repository, pending upstream availability review.
No Git history, Cargo credentials, production configuration, runtime data or
entire Cargo caches are copied into the snapshot or artifacts.
